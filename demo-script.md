# 45-minute X Trust Demo Script

## 1. Positioning (5 min)
X already owns software quality/security clearance for its BFSI products. Position ASPM as a control plane that strengthens this existing process rather than replacing X's security team.

Key message: **"You remain the authority; we give you continuous evidence, automation and traceability."**

## 2. Software composition + SBOM (8 min)
Show the application, package manifest, generated component inventory and dependency relationships. Explain how the SBOM becomes reusable security evidence for internal release approval and downstream customer assurance.

## 3. SCA (7 min)
Show vulnerable/open-source dependencies, severity, package version, fix version where available, and dependency path. Explain how X can prevent vulnerable libraries from silently entering multiple customer releases.

## 4. SAST (8 min)
Walk from finding to source for SQL injection, command injection, weak hashing and hard-coded authentication material. Emphasize developer-friendly remediation context and ownership.

## 5. Secrets (5 min)
Show fake AWS/GitHub/payment-style credential patterns. Explain pre-merge detection, repository history exposure and centralized governance. State clearly that all demo secrets are non-functional.

## 6. ASPM control plane (8 min)
Show normalization/deduplication, application/repository grouping, risk prioritization, policy gates, workflow/ticket integration, SLA tracking, exception management, trend reporting and audit evidence.

## 7. Partnership / X value (4 min)
Frame three adoption models:
- Internal security clearance for X's own software.
- Security evidence package accompanying releases to X's BFSI customers.
- Optional managed/embedded AppSec capability that X can standardize across multiple customers.

Close with a jointly defined pilot using one representative X application and mutually agreed success criteria.
